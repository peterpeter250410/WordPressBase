## 1. 现状诊断

### 1.1 技术 SEO 得分：接近零

代码级核查（`wp-content/themes/wpbase-starter/`）结果：

| 项目 | 现状 | 影响 | 优先级 |
|---|---|---|---|
| `<title>` | 有 `title-tag` 支持，但无自定义模板 | 全站标题是「页面名 - 站点名」，无关键词布局 | P0 |
| meta description | **完全没有** | 搜索结果摘要由 Google 随机截取，CTR 无法控制 | P0 |
| canonical | **完全没有** | 重复内容风险 | P0 |
| **hreflang** | **完全没有** | **三语站最致命缺口，详见 §1.2** | **P0** |
| OG / Twitter Card | 没有 | LINE/微信/X 分享无缩略图，社交流量归零 | P1 |
| JSON-LD 结构化数据 | 没有 | 拿不到富媒体结果、无法建立实体识别 | P0 |
| robots.txt | 无自定义 | 无 sitemap 声明 | P1 |
| sitemap | WP 默认 `wp-sitemap.xml` | **只含日文 URL，`/zh/` `/en/` 完全没有收录入口** | P0 |
| 面包屑结构化数据 | 视觉面包屑有，无 `BreadcrumbList` | 搜索结果不显示路径 | P1 |
| 图片 alt | 部分缺失 | 图片搜索流量归零 + 可访问性 | P1 |
| 404 处理 | 有 `404.php` | 需确认返回真 404 状态码 | P2 |

### 1.2 三语架构的结构性风险（最高优先级）

当前架构（`functions.php` 第 14–105 行）：日文根目录，`/zh/` `/en/` 前缀被剥离后走**同一套模板**，靠 `locale` 过滤器切 `.mo` 实现翻译。

工程上很优雅，但对搜索引擎有四个硬伤：

**① 无 hreflang → 三语互相当作重复内容**
Google 看到 `/`、`/zh/`、`/en/` 三个 URL 结构相同、图片相同、布局相同，在没有 hreflang 声明的情况下无法判断它们是「同一内容的不同语言版本」。典型后果是选一个作规范版本、另外两个标记为 `Duplicate, Google chose different canonical` 而**不予收录**。

**② `redirect_canonical` 被整体关闭 → URL 变体全部返回 200**
```php
// functions.php:63
add_filter('redirect_canonical', function ($redirect_url) {
    return (eikou_current_lang() !== 'ja') ? false : $redirect_url;
});
```
这行是为了避免前缀剥离导致的重定向死循环，必要且正确。但副作用是次级语言下 `/zh/about`、`/zh/about/`、`/zh/about/?x=1` 全部返回 200 且内容相同 —— 在没有 canonical 标签兜底的情况下，重复内容敞口被放大。**必须用 canonical 补上**，不能改回重定向。

**③ sitemap 不含次级语言**
`eikou_localize_url()` 明确排除了 `wp-sitemap`（第 78 行），所以 `wp-sitemap.xml` 里全是日文 URL。`/zh/` `/en/` 只能靠站内链接被爬到，收录速度和覆盖率都会很差。

**④ 动态内容不翻译 → 次级语言页面是「劣质页」**
`docs/i18n-deploy.md` 已注明：后台录入的作品/视频/合作伙伴文章标题正文**不走 `.mo`**。也就是 `/en/works/` 这个页面，框架是英文、案例标题是日文。Google 对「声明为 en 但正文大量非目标语言」的页面评价很低，容易整体降权。这是 §3 内容策略必须解决的问题。

> **结论：技术地基不修，后面所有内容和外链投入在 `/zh/` `/en/` 上的回报接近于零。** 这是 P0 中的 P0。

### 1.3 已有资产（被严重浪费的部分）

这是本项目最大的意外收获：

- **`eikou_get_service_items()` 里有 24 个服务条目**，每条都带 `title` / `title_en` / 300+ 字 `description` / 6 条 `features` / 3 条 `points` / 4 个 `tags`。这是**已经写好的、结构化的、高质量的长尾内容**。
- 24 条 × 3 语言 = **72 个可直接产出的长尾落地页**，且内容已存在。
- 6 个服务大类（展示会・イベント 7 / ブランドイベント 5 / デジタル 3 / AI 3 / ブランディング 3 / メディア 3）天然构成 6 个主题簇（topic cluster），是内链权重雕刻的现成骨架。
- 4 个 CPT（work / eikou_video / partner / testimonial）+ `work_category` 分类法，具备案例库扩展能力。
- 真实企业实体信息完整：荣光株式会社（EIKOU Co., Ltd.）／2009 年设立／〒125-0052 東京都葛飾区柴又1丁目43-6 MAC柴又コート 102／TEL 03-5876-9273／info@eikoujp.net —— 这是 LocalBusiness 结构化数据和 citation 建设的完整原料。

**判断：本站不缺内容，缺的是让搜索引擎看得见内容的管道。** 这决定了本方案的资源分配 —— 前两周全砸技术，不写一个字新内容。

## 2. 关键词战略

### 2.1 定位判断

荣光的差异化不是「日本的展会搭建公司」（这个赛道日本本土公司几百家，且他们有几十年的域名年龄和行业协会背书），而是：

> **能用日/中/英三语，把海外企业（特别是中国企业）接进日本展会现场的一站式服务商。**

这个定位对应的搜索需求，日本本土公司吃不到（不做中文），中国公司也吃不到（没有日本落地能力和日本本土案例）。**三语站在这里不是成本，是护城河。** 全部关键词战略围绕这一点展开。

### 2.3 英文（价值密度最高）

主攻**海外企业到日本参展**这个被严重忽视的需求：

- `exhibition booth design Japan` / `trade show booth builder Tokyo`

英文赛道的竞争者主要是国际展会搭建集团的日本页（内容浅、无本土案例），荣光有真实日本本土施工实绩 + 500 件以上实绩数据，内容深度可以直接碾压。**这是三语里 ROI 最高的一块，建议英文优先级高于中文。**

### 2.4 中文（需要现实预期管理）

**必须先说清楚一件事：百度 SEO 在本项目里 ROI 很低。** 原因：
1. 服务器在日本、无 ICP 备案 —— 百度对无备案境外站点的收录和排名有系统性压制；
2. 百度近年自然搜索结果位大幅让位于自有产品和竞价；
3. 目标客群（想去日本参展的中国企业主/市场负责人）真实的信息获取路径已经不在百度。

**因此中文策略调整为：**

| 渠道 | 做法 | 优先级 |
|---|---|---|
| **Google 中文** | `/zh/` 页面做好 hreflang + 中文关键词，吃「日本展会搭建」「东京展台设计」「日本参展一条龙」等词的 Google 中文结果（海外华人、出海企业、外贸公司都用 Google）| 高 |
| **微信搜一搜** | 建服务号，内容与 `/zh/` 同源改写，微信生态内搜索独立于百度 | 中 |
| **小红书 / 知乎** | 「日本参展避坑」「东京展会搭建报价」类内容，导流到 `/zh/contact` | 中 |
| **百度** | 只做品牌词保护（百度百科词条 + 官网提交），不投入长尾 | 低 |

中文核心词：`日本展会搭建` / `东京展台设计` / `日本参展 一条龙` / `日本展会 布展 公司` / `日本落地服务 展会`

## 3. 页面架构与内容战略

### 3.1 主题簇（Topic Cluster）架构

把现有 6 大服务类目做成 6 个封闭的主题簇，权重在簇内循环、由簇心页向上汇聚：

```
首页（品牌 + 实体权威）
 ├─ 服务总览页（/services/）……… 枢纽
 │   ├─ 簇1 展示会・イベント（簇心）
 │   │    └─ 7 个服务详情页（已有内容）
 │   ├─ 簇2 ブランドイベント（簇心）
 │   │    └─ 5 个服务详情页（已有内容）
 │   ├─ 簇3 デジタル・Web ── 3 页
 │   ├─ 簇4 AIソリューション ── 3 页
 │   ├─ 簇5 ブランディング ── 3 页
 │   └─ 簇6 メディア・映像 ── 3 页
 ├─ 场馆页群（新建，§3.2）→ 横向链入相关服务页
 ├─ 案例库 /works/ → 每个案例链回其服务页与场馆页
 └─ 资源中心（新建）→ 費用相場 / 出展ガイド / FAQ
```

**规则：** 每个服务详情页必须链向 ① 所属簇心 ② 同簇 2–3 个兄弟页 ③ 至少 1 个相关案例 ④ 联系页。这个规则由代码自动执行，不靠人工维护（见执行文档）。

### 3.2 程序化扩页（灰帽加速的核心，也是风险控制的关键）

**第一批 · 场馆页（15 页 × 3 语言 = 45 页）**

日本主要展馆各建一页：東京ビッグサイト / 幕張メッセ / パシフィコ横浜 / インテックス大阪 / ポートメッセなごや / 東京国際フォーラム / makuhari / 神戸国際展示場 / 札幌ドーム / マリンメッセ福岡 等。

每页包含：场馆规格数据、搬入搬出规则、常见小間割、该场馆的施工注意点、**荣光在该场馆的实际案例**、报价引导。

> **这类页面是真实有用的**——参展方确实会搜「東京ビッグサイト 搬入 ルール」。所以它是白帽内容，只是用程序化方式规模化生产。

**第二批 · 展会页（20–30 页 × 3 语言）**

主要展会各建一页：CEATEC / 東京ゲームショウ / FOODEX JAPAN / JAPAN MOBILITY SHOW / 国際宝飾展 / インターフェックス 等。内容为该展会的出展指南 + 荣光的对应服务。

**第三批 · 服务 × 场馆交叉页（受严格管控）**

`東京ビッグサイト × ブース施工`、`幕張メッセ × 展示什器` 这类交叉页是流量放大器，但**也是本方案里唯一可能滑向桥页（doorway page）的地方**。

**硬性质量门槛（写进生成脚本，不达标不生成）：**
1. 必须有该场馆的**真实案例**（含实拍图）才允许生成对应交叉页；
2. 正文与其他交叉页的重复率 < 40%（模板句式必须变体化）；
3. 每页至少 800 字实质内容 + 3 张原创图；
4. 单批上线不超过 20 页，间隔 2 周观察收录率。

达不到门槛的组合**不生成**。宁可少 100 页，不要一次被判定为批量低质页面。

### 3.3 解决 §1.2④「次级语言内容不翻译」

这是 `/zh/` `/en/` 能否真正拿到流量的前提，三选一：

| 方案 | 做法 | 评价 |
|---|---|---|
| **A. 译文入库（推荐）** | 给 CPT 加 `_title_zh` / `_title_en` / `_content_zh` / `_content_en` 元字段，前端按语言取；用脚本 + AI 批量填充，人工校对 | 改动可控，与现有 `.mo` 架构不冲突，质量可控 |
| B. 逐语言建文章 | 每个案例建 3 篇 | 后台维护成本 ×3，与现有架构冲突 |
| C. 次级语言 noindex | `/zh/` `/en/` 的案例页不收录 | 放弃两个语种的长尾，不可接受 |

**采用 A。** 人工校对资源用在这里（而非首页文案），单位投入产出最高。

## 5. 灰帽手段清单（逐条附风险敞口，供你判断）

按「收益 / 风险」排序，前 5 条建议直接执行，后 3 条需你单独拍板。

### ✅ G1. 内链权重雕刻（Link Sculpting）— 零风险，收益高
用代码自动构建 hub-spoke 内链网络、控制锚文本分布、给转化页倾斜权重。**这是纯技术手段，无任何判罚风险**，只是大多数企业站不做。优先级最高。

### ✅ G2. 程序化扩页 — 低风险（有质量门槛的前提下）
即 §3.2。风险完全取决于质量门槛是否严格执行。门槛写进脚本、不达标不生成，风险可控。

### ✅ G3. 实体 SEO / Citation 堆叠 — 零风险，日本本地 B2B 的最高 ROI
在 30+ 个日本商业目录（iタウンページ、Wantedly、エキテン、Baseconnect、Musubu 等）建立 NAP 完全一致的企业档案，并全部 `sameAs` 串联到官网。Google 对日本本地企业的实体识别高度依赖这类信号。**成本低、见效稳、无风险，是被最多人低估的一招。**

### ✅ G4. 竞对内容逆向 — 零风险
抓取竞对 sitemap + 排名词，做关键词缺口矩阵，在其薄弱页系统性地做更深内容。属于标准竞争情报，不涉及任何违规。

### ✅ G5. 新鲜度信号操纵 — 极低风险
系统性维护 `dateModified`、定期实质性更新旧页、用 `lastmod` 引导重爬。**注意：必须是实质性更新**，只改日期不改内容属于欺骗性行为，Google 已能识别并会降低对该站 `lastmod` 的信任度（后果是重爬变慢，反噬）。

### ⚠️ G6. 老域名 301 权重转移 — 中风险，需拍板
收购日本展会/活动行业的过期老域名，301 到主站相关页。
- **有效前提**：域名主题与荣光高度相关 + 历史干净 + 有真实反链。
- **失效场景**：主题不相关的 301 会被 Google 直接忽略（当作软 404），钱白花。
- **风险场景**：老域名有垃圾反链历史 → 把负面信号引进主站，且难以剥离。
- **尽调要求**：Wayback Machine 查历史用途、Ahrefs/Majestic 查反链质量与锚文本分布、查是否曾被判罚。
- **建议**：可以做，但**先 301 到一个子目录观察 3 个月**，确认无负面影响再指向核心页。

### ⚠️ G7. 卫星站 / 站群 — 中高风险，需拍板
建独立站点反链主站。这里必须区分两种做法：

| 做法 | 说明 | 风险 |
|---|---|---|
| **真媒体站（建议）** | 建一个「展示会ナビ」类的行业资讯站，有真实编辑价值、独立运营、自然提及荣光 | 低。这本质是内容营销，不是链接方案 |
| **PBN（不建议）** | 5–10 个仅为反链存在的空壳站 | 高。同源特征（注册信息/服务器/模板/发文节奏）极易被识别，判罚是链接方案惩罚，**主站连坐** |

**建议只做前者，且只做一个。** 一个真正有人看的行业站，价值超过 10 个 PBN，且是资产而非负债。

### ⚠️ G8. 付费外链 — 中风险，需拍板
日本市场的现实是：行业目录付费收录、媒体付费投稿（PR TIMES 等）是**普遍且半公开**的行业惯例，与英文市场的「买链」性质不同。
- **可接受**：PR TIMES 等正规发布平台、行业协会付费会员目录、展会媒体的赞助文章（带 `sponsored` 标记）。
- **不接受**：链接农场、Fiverr 批量外链包、评论/论坛群发。后者不仅无效，且会触发链接方案判罚。
- **预算建议**：优先投 PR TIMES + 行业协会会员费，而非任何形式的「外链套餐」。

## 6. 明确排除的手法（及排除理由）

| 手法 | 排除理由 |
|---|---|
| Cloaking（对爬虫和用户返回不同内容）| 一旦判定为整站级判罚，品牌词消失。**且本站已有 UA 动态服务架构（H5/PC 双模板），本就处于灰色地带边缘，绝不能再往前一步** |
| 桥页 / Doorway Pages | 与 §3.2 交叉页只有一线之隔，靠质量门槛守住这条线 |
| 隐藏文本 / 关键词堆砌 | 收益早已归零（Google 2003 年起就能识别），纯风险 |
| 采集站 / 内容洗稿 | 与荣光「有真实实绩」的核心优势背道而驰 |
| 评论/论坛/Wiki 群发外链 | 无效且触发链接方案判罚；且属于污染第三方站点 |
| 负面 SEO（攻击竞对）| 不做 |
